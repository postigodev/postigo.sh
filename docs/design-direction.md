# Design Direction

## Working concept

This portfolio is a **personal desktop / field archive**.

It combines the interaction logic of an old desktop operating environment with the cultural texture of early personal websites, dark MySpace layouts, low-fidelity digital media, archival print, and a restrained cybergrunge sensibility.

It is not a Windows 98 recreation.

It is a fictional personal operating system that happens to inherit some of the interaction grammar of Windows-era desktops.

The visitor should feel like they have entered a specific person's computer rather than opened a themed portfolio template.

## Core tension

The design is built around:

**60% structural minimalism  
40% expressive maximalism**

Structural minimalism means:
- clear information hierarchy
- fast access to important content
- deliberate initial composition
- readable typography
- restrained number of visible windows
- generous negative space where useful
- predictable navigation
- professional credibility

Expressive maximalism means:
- texture
- personal-web density
- overlapping windows during exploration
- low-fidelity imagery
- weird small details
- system metadata
- archival visual artifacts
- unusual typography used selectively
- goat branding
- controlled disorder

The site should become visually denser as the visitor interacts with it.

## Primary references

### Dark MySpace / personal homepage culture

This is the strongest vibe reference.

Important qualities:
- black background
- white/light text
- irregular modular blocks
- image + text + status + interests + media existing together
- intimate/personal rather than productized
- imperfect visual rhythm
- strong sense of an individual author
- early-web density without modern dashboard polish
- a page that feels inhabited

Do not copy MySpace chrome literally.

Capture the **personal authorship and density**.

### Stitch concepts

Use for:
- dark archival desktop atmosphere
- black panels/windows
- cobalt/system-blue title bars or accents
- `SYSTEMS THINKER` / systems-oriented identity language
- side widgets
- taskbar/footer micro-information
- subtle goat emblem
- dirty photographic surface
- contrast between UI chrome and content

Do not preserve Stitch layout simply because it was generated.

### WIN98-template

Use primarily for interaction grammar:
- draggable windows
- minimize/maximize/close
- taskbar
- Start-style launcher
- icon selection
- active/inactive windows

The production visual language should diverge substantially from stock Windows 98.

## Design thesis

The portfolio should feel like:

> a contemporary professional portfolio discovered inside a strange, personal, meticulously maintained computer from another era.

Other useful descriptions:

- clean core, dirty skin
- professional shell, underground signal
- personal web as operating system
- digital field archive
- inhabited computer, not retro theme
- maintained, not pristine

## Emotional tone

Desired:
- intelligent
- curious
- slightly strange
- personal
- technically serious
- internet-native
- underground but controlled
- archival
- nocturnal
- dry/deadpan humor
- handmade without looking amateur

Avoid:
- corporate friendliness
- shiny product-design optimism
- futuristic cyberpunk
- gothic darkness
- nostalgia cosplay
- ironic meme overload
- generic brutalism
- gamer UI
- hacker-movie terminal cliché

## Desktop as hero

There does not need to be a conventional landing-page hero.

**The desktop itself is the hero.**

The first screen should already communicate:
- who Piero is
- what domains he works/thinks in
- that the environment is interactive
- where Work / Resume / About / Contact live

The default first-visit composition should feel authored.

Recommended:
- one dominant identity/profile window already open
- several recognizable desktop icons
- optional small now-playing/status surface
- taskbar
- enough background visible to invite exploration

Avoid opening so many windows that first load looks chaotic.

## Identity window

The primary identity window should feel more like a personal profile/homepage surface than a corporate hero card.

Possible content:
- name
- avatar or deliberately low-fi personal image
- `CS × PSYCHOLOGY`
- concise statement about software / behavior / systems
- status metadata
- location/availability when appropriate
- direct routes to Work / About / Resume / Contact
- subtle goat mark

The identity window should be the fastest way to understand the person behind the portfolio.

## Goat branding

The goat emoji/mark is a canonical personal symbol.

Use it as:
- OS emblem
- desktop icon
- favicon candidate
- verification stamp
- small titlebar/system mark
- boot/loading detail
- occasional bureaucratic signature

Desired tone:
- deadpan
- official
- slightly absurd
- understated

Good:
`verified by the goat`

Bad:
`🔥 GOAT MODE ACTIVATED 🔥`

Do not turn the portfolio into goat-themed novelty design.

## Color

### Dominant surfaces

Prefer:
- near-black
- charcoal
- graphite
- dirty dark gray
- CRT-like black
- faded system gray

### Light surfaces

Use selectively:
- bone
- aged paper
- warm gray
- old Windows gray
- dirty white

Light panels should feel like objects inside a darker environment, not the default page background.

### Digital accent

Cobalt / classic system blue is the main accent.

It can appear in:
- title bars
- selection
- active state
- links
- small labels
- focus indicators

### Secondary signals

Use sparingly:
- signal green
- warning red
- muted amber/yellow

Do not create a rainbow UI.

## Surface language

The interface may include:
- 1px hard borders
- beveled edges
- old-system control geometry
- black panels
- dirty gray panels
- rectangular buttons
- active/inactive title states
- dotted selection
- classic resize affordances
- visible state changes

Avoid:
- rounded SaaS cards
- floating glass panels
- modern gradient blobs
- excessive shadows
- huge border radii

If rounding exists at all, it should belong to the outer hardware/viewport metaphor rather than every component.

## Materiality

The site should not feel like a perfectly exported Figma frame.

Desired traces:
- dithering
- halftone
- subtle JPEG artifacts
- grain
- scanner noise
- photocopy texture
- low-res photography
- uneven printed/archival edges
- compressed thumbnails
- monochrome or limited-color images

Materiality should be controlled and intentional.

Do not cover every element with noise.

Some regions should remain visually quiet so textured regions have impact.

## Images

Image treatment is an important source of personality.

Good directions:
- low-resolution digital camera feel
- flash photography
- grayscale
- dithered 1-bit / low-bit conversion
- photocopy
- halftone
- scanner-like treatment
- contact sheet
- archival screenshots
- technical diagrams
- real project evidence

Prefer images that feel like **evidence** rather than generic decorative artwork.

Avoid generic AI-looking abstract 3D hero images.

## Typography

Typography should feel like layers from the same personal computer environment.

### UI/body

Use a highly legible system-like sans or pixel-adjacent UI face.

Role:
- buttons
- window chrome
- navigation
- descriptions
- taskbar
- labels

### Mono/system

Role:
- metadata
- terminal
- file paths
- build/version text
- timestamps
- diagnostics

### Display

Use one expressive digital/Y2K display face selectively.

The previously explored direction favored:
- `Superdigital` for major identity/display moments
- `PixdorTwo` as a possible quieter secondary digital voice
- distressed faces such as `Acidic` only as rare artifact accents

Exact production fonts depend on local files and licensing.

Avoid using multiple novelty fonts at once.

Do not default back to fashion-editorial serif typography unless there is a clear contextual reason.

## Type contrast

A useful hierarchy:

```text
LARGE DIGITAL DISPLAY
×
precise UI sans
×
small mono metadata
×
rare distressed artifact text
```

Display type should be rare enough to remain memorable.

## Windows

Windows are the main content containers.

They should:
- feel interactive
- clearly expose active/inactive state
- have titlebars
- have usable controls
- contain real portfolio content
- vary in size based on content

Do not make every content block a separate window.

The metaphor becomes weaker if everything is chrome.

Some content can live within an Explorer-like app, document view, or project app.

## Window density

Initial state:
- restrained
- easy to parse
- one dominant window
- maybe one small secondary window/widget

Explored state:
- may become dense
- overlaps are allowed
- user creates their own composition

This is an important part of the 60/40 design logic.

## Desktop icons

Icons should map to meaningful destinations.

Candidate desktop objects:
- Work
- Resume
- About
- Notes / Writing
- Contact / Network
- optional Terminal
- goat/system object

Avoid filling the screen with fake icons solely for nostalgia.

## Taskbar

Taskbar should provide:
- visible running/open apps
- restore/minimize affordance
- launcher/start control
- clock/status
- possibly small system/goat mark

Keep it efficient and recognizable.

It should not become an information ticker full of unreadable decoration.

## Work / Projects

Projects are professional evidence first.

The presentation can be playful, but each featured project should quickly communicate:
- name
- what it is
- what Piero contributed
- relevant technologies
- meaningful evidence/result
- source/live links where appropriate

Potential metaphors:
- Explorer folder
- executable/app icons
- project windows
- archive entries
- `.log` / `.sys` / `.exe` naming used sparingly

Do not let file-extension jokes obscure project names.

## About

About should be more personal than a résumé summary.

Possible material:
- CS + Psychology intersection
- systems/behavior/design interests
- selected current interests
- current reading/listening
- personal web flavor

Avoid generic:
`I'm passionate about building innovative solutions...`

## Resume

Resume must be straightforward to reach.

The desktop metaphor can frame it as a PDF/document, but:
- allow direct download/open
- provide a normal `/resume` route
- do not make recruiters solve a puzzle to access it

## Notes / Writing

This is a natural place for the archival/personal-web side to become richer.

Possible treatments:
- text files
- zine/archive viewer
- notes folder
- dated entries
- external writing links

Keep professional portfolio priorities above experimental publishing features on first load.

## Now Playing

A small media/status widget fits the personal-web influence.

It should:
- be optional
- never autoplay
- not load heavy media immediately
- remain secondary to identity/work

The value is cultural/personal context, not a full streaming app.

## Terminal

Terminal is an optional enhancement.

If implemented:
- useful commands first
- lightweight
- keyboard accessible
- no fake "hacking" theater

Possible commands:
- `whoami`
- `work`
- `about`
- `resume`
- `contact`
- `clear`
- `goat`

Do not prioritize this before core portfolio content.

## Motion and interaction

Motion should feel mechanical rather than silky-modern.

Prefer:
- immediate window snapping
- short minimize/open transitions
- simple focus changes
- old-UI tactility

Avoid:
- spring-heavy animation
- floating parallax
- cinematic page transitions
- constant background movement

Respect `prefers-reduced-motion`.

## Cursor

A custom cursor may be explored later.

It must not:
- reduce precision
- harm accessibility
- interfere with native text/select interactions

Not required for first implementation.

## Background

The desktop background should be visually meaningful.

Strong direction:
- dark scraped/scanned surface
- subtle repeating texture
- enough contrast for windows/icons
- not a giant photographic wallpaper competing with content

The background should create atmosphere while remaining a functional desktop surface.

## Professional usability

A visitor with 30–60 seconds should be able to find:
- identity
- selected work
- resume
- contact

The interactive metaphor should reward exploration without punishing efficiency.

This is especially important for recruiters and engineering peers.

## Mobile

Mobile should reinterpret the system, not shrink it.

Desired:
- app-launcher feel
- windows become fullscreen/stacked
- clear Back/Close behavior
- persistent access to Work/Resume/Contact
- same design language, reduced spatial gimmick

Do not require dragging on touch screens.

## Accessibility

Visual weirdness should not produce semantic weirdness.

Preserve:
- readable type
- clear focus states
- keyboard navigation
- semantic links/buttons
- alt text
- contrast
- reduced-motion support

The old-web look is aesthetic; accessibility standards remain contemporary.

## Performance as aesthetic integrity

A site inspired by early personal computing should feel immediate.

It would be contradictory for a visually lightweight old-web portfolio to load like a modern ad-heavy application.

Priorities:
- fast first render
- minimal JS
- small images
- no initial embeds
- lazy secondary apps
- no autoplay
- no unnecessary analytics
- self-hosted/static assets where practical

The portfolio may look technologically old, but it should feel technically excellent.

## Anti-goals

Do not produce:
- a Windows 98 clone with Piero's text inserted
- a generic retro developer portfolio
- a dashboard full of cards
- a SaaS page wearing grain overlays
- cyberpunk neon
- maximalist collage with weak navigation
- a static screenshot pretending to be a desktop
- an art project that hides career evidence
- an overly corporate portfolio with decorative retro stickers

## Success condition

The final site should make a visitor think:

> this is clearly a serious software portfolio, but I haven't seen this exact personal system before.

The aesthetic should make the work memorable.

The work should make the aesthetic credible.
